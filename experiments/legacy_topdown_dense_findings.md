# Eight-qubit top-down verification with vectors and matrices

Completed 2026-09-14. The quoted training numbers are substantially recoverable,
but they do **not** establish the claimed noisy-fidelity ranking. Independent
density-matrix scoring reverses the top-down versus layerwise comparison on
the matching TFIM example. This is a verification of the retained scripts,
not a claim that every implementation of the proposed method must fail.

## Where the numbers came from

The current [plotting script](../scripts/plot_paper_figures.py) hard-codes
`[0.6468, 0.9128, 0.9600]` and parameter counts `[150, 276, 150]`. It labels
the example State 4 and does not load numerical results or checkpoints.
The old experiment scripts are retained in Git at
`6bdc86baeb7daa03756f153b49fda0d7606d04d5`:

- `experiments/baselines_benchmark.py`: reproduces the VQA number for TFIM seed
  400, using initialization seed 42 and training seed 1.
- `experiments/adapt_noisy_test.py`: reproduces the 150-parameter layerwise
  number for TFIM seed 400, using initialization seeds 100/202 and noisy
  training seed 800.
- `experiments/find_hero_state.py`: contains the closest complete impact-pruned
  comparison. Its committed target seed is 300. Repeating its settings with
  seed 400 gives 95.9186% top-down training fidelity, close to the hard-coded
  96.00%, but not an exact reproduction of 96.00%.
- `experiments/impact_pruning_benchmark.py`: another iterative rank-pruning
  variant, with different settings including weakly noisy pretraining.

The matching rows below therefore reconstruct the example from separate
archived scripts; they were not all generated by one retained combined run.
The exact 96.00% checkpoint was not found. The VQA count is **276**, not 275.
Copies of the source scripts, trained parameters, explicit target vectors,
complete training traces, and circuit gate lists are retained in the output
directories linked below.

The last reported three-trajectory samples contained these jump counts:

| Method    | Jumps in each trajectory | Sampling setting      |
| --------- | ------------------------ | --------------------- |
| VQA       | 1, 0, 0                  | Frozen CRN            |
| Layerwise | 0, 0, 2                  | Resampled each update |
| Top-down  | **0, 0, 0**              | Frozen CRN            |

The top-down training fidelity equals its noiseless fidelity because every
frozen trajectory has no jump. Conversely, the layerwise result is penalized
by its particular last sample. Three sampled trajectories can produce a very
misleading ranking even when the simulator and optimizer are functioning.
Exact density evaluation eliminates this sampling uncertainty for the stated
channel; it does not eliminate uncertainty about an actual device's noise.

The [seed-300 combined-script rerun](../output/legacy-topdown-dense-20260914/archived_tfim_300)
also does not show dominance: exact IBM-profile fidelities are 68.6644% for
fixed VQA, 86.0596% for layerwise, and 57.5241% for top-down. On both reruns,
pruning initially damages fidelity substantially; the subsequent recovery
is strongly instance-dependent. Two exploratory TFIM seeds do not establish
a general performance ordering.

## Literal interpretation of the stated four-step method

This was tested separately because it differs from the archived comparison:

1. Start at depth 1, add one depth at a time, retaining existing parameters and
   initializing added parameters near zero.
2. Use 200 updates per depth: up to 100 online Krotov sweeps followed by batch
   updates, step size 0.7. Check fidelity after every update and stop at 90%.
3. Compute the exact noiseless derivative and delete every gate whose
   `abs(theta * dF/dtheta) < 0.01`. Absolute value follows the archival impact
   definition; a signed cutoff would remove still more parameters.
4. Fine-tune with 100 online plus 100 batch updates, step size 0.2, three
   frozen cross trajectories, independently for both archived noise profiles.
   Continue the same unpruned circuit as a control.

The step sizes, iteration budgets, and three-trajectory count are explicit
experimental choices where the user's description left settings unspecified.
This is one literal-method diagnostic, not a comprehensive hyperparameter search.
Both targets use seed 300. The Haar vector uses independent normal real and
imaginary components followed by normalization.

| Target              | Depth at first 90% | Updates | Parameters before pruning | Noiseless fidelity | Largest impact | Parameters retained | Fidelity after pruning/fine-tuning |
| ------------------- | -----------------: | ------: | ------------------------: | -----------------: | -------------: | ------------------: | ---------------------------------: |
| Disordered TFIM     |                  1 |     138 |                        87 |           90.0123% |     0.00593164 |               **0** |                           10.0023% |
| Complex Haar random |                 12 |    2213 |                       780 |           90.0045% |     0.00556575 |               **0** |                            0.4723% |

The empty circuits have no parameters to repair. This is a property of the
specified cutoff applied to these trained states. A small first derivative
does not certify that deleting a gate has small finite effect: at a stationary
point every first derivative vanishes, including those of essential gates.

The historical script instead ranks impacts, removes at most 150 parameters
per pruning round, relaxes for 40 noiseless batch updates between rounds, and
stops with 150 retained parameters. It does **not** use the absolute 0.01 rule.
Its pretraining also uses batch-only updates at depths 4, 8, 12, 16, rather
than the literal hybrid/depth-one protocol. Those differences matter.

## Vector and matrix formulation

Each trajectory is a complex128 vector with 256 amplitudes. For fixed sampled
Pauli jump maps and gate matrices,

\[
|\psi*{r,k}\rangle=J*{r,k}U*k(\theta_k)|\psi*{r,k-1}\rangle,
\qquad
\widehat F=\frac1R\sum*r|\langle\phi|\psi*{r,G}\rangle|^2.
\]

The physical ensemble is the average of outer products,
`rho = mean(psi_r psi_r.conj().T)`, rather than the outer product of an
averaged state vector. CRN fixes the sampled maps during optimization.
It makes that finite-sample objective deterministic; it does not make its
value equal to the ensemble expectation.

The independent loss gradient differentiates `1 - mean(fidelity_r)` exactly.
The archived cross update uses all forward-prefix/backward-suffix trajectory
pairings. The dense runner preserves that update. Cross mode need not be the
gradient of the same finite frozen-sample objective, so this reproduction
does not infer a convergence guarantee from the word “gradient.”

For an exact ensemble evaluation, start with a 256-by-256 density matrix
`rho_0 = |0...0><0...0|` and propagate

\[
\rho*k=\mathcal E_k\bigl(U_k\rho*{k-1}U_k^\dagger\bigr),
\qquad F=\langle\phi|\rho_G|\phi\rangle.
\]

The archived CTJM implementation permits at most one jump in each gate window.
For local Pauli rates `gamma_a`, duration 1, and `Gamma = sum(gamma_a)`, its
exactly averaged channel is

\[
\mathcal E(\rho)=e^{-\Gamma}\rho+
(1-e^{-\Gamma})\sum_a\frac{\gamma_a}{\Gamma}P_a\rho P_a^\dagger.
\]

Qiskit constructs the elementary rotations independently of YAQS and applies
the above local superoperators to full density matrices. A second evaluator
uses the full Lindblad exponential, allowing repeated jumps. Across all 27
saved checkpoints and both profiles, the largest fidelity difference between
those two laws is 0.00015534 (0.015534 percentage points). That distinction
cannot explain the ranking reversal.

The IBM-inspired rates are `3e-4/3` for each single-site X/Y/Z and `3e-3/2`
for correlated XX/ZZ on a two-qubit gate. Google-inspired rates are `6e-4/3`
and `5e-3/3` for X/Y/Z and XX/YY/ZZ. Local single-site processes also act on
both sites of two-qubit gates, exactly as in the archived code. These are
anisotropic correlated Pauli models, not full two-qubit isotropic depolarization
or a reconstruction of real hardware calibration data.

The resulting average gate infidelities are:

| Profile         | One-qubit infidelity | Two-qubit infidelity |
| --------------- | -------------------: | -------------------: |
| IBM-inspired    |           0.0199970% |           0.2874822% |
| Google-inspired |           0.0399880% |           0.4944656% |

These derived values distinguish the code's rates from measured gate errors.
This study retains the archive's numerical settings; it does not verify current
IBM or Google specifications or predict a QPU execution.

The baseline called ADAPT is predetermined layerwise BMPD growth. It does not
select operators from a pool by their gradients, as in
[Grimsley et al.](https://arxiv.org/abs/1812.11173). The fixed baseline is also
trained by the repository's batch Krotov routine; it is not a reproduction of
the complete hardware VQE experiment in
[Kandala et al.](https://arxiv.org/abs/1704.05018). Optimization work differs
between arms. Neither the plotted values nor this rerun establishes an
advantage against a properly matched implementation of either paper.

## Reproduction and artifacts

The [driver](legacy_topdown_dense.py) performs training using dense vectors;
no MPS/MPO simulation participates in the experiment. Tests independently check
its elementary updates against the production MPS code. Exact adjoints replace
the archive's parameter-shift pruning derivatives, with numerical equivalence
tested before running.

```sh
uv run python -m experiments.legacy_topdown_dense \
  --output NEW_SEED300_DIRECTORY --arm all --seed 300
uv run python -m experiments.legacy_topdown_dense \
  --output NEW_SEED400_DIRECTORY --arm archived --seed 400
uv run python -m experiments.legacy_topdown_dense \
  --output NEW_BASELINES_DIRECTORY --arm baselines --seed 400
```

The original seed-300 run predates the separate baseline CLI addition; its
`all` arm contains archived and literal runs only. Exact driver source for each
completed invocation is retained as `driver_source.txt` with its manifest hash.
The current `all` additionally runs the separate baseline settings.

```python
import numpy as np

data = np.load("output/legacy-topdown-dense-20260914-seed400/matrices/topdown.npz")
fidelity = np.vdot(data["target"], data["rho_IBM"] @ data["target"]).real
assert np.isclose(fidelity, 0.8169830221008296)
```

Verification covers noiseless vector/matrix equality, parameter shifts, actual
jump replay against MPS, exact enumerated channel gradients against independent
matrix finite differences, channel positivity/trace preservation, physical gate
deletion, first-threshold stopping, and checkpoint reload. All saved density
matrices pass trace, Hermiticity, and positivity checks at 1e-10 tolerance;
noiseless vector/matrix fidelity differences are below 4e-15.

The targeted test suite, Ruff checks, and targeted type checks pass. The required
repository-wide `uvx nox -s lint` was attempted but is blocked by existing
plot/manuscript lint errors, a broken Homebrew Node/simdjson dependency, and
type errors in unrelated archived output snapshots. Unrelated files changed
automatically by those hooks were restored to their pre-run contents.
