# Complete best-candidate confirmation

This protocol is implementation only until the coordinator selects one of two
fully developed recipes and explicitly freezes its design. No held-out state
is loaded, simulated, constructed or scored during implementation or tests.
The executable entry point is `python -m
experiments.overnight_state_preparation_20260913_0108.best_candidate`.

## Design before target access

`--freeze-design --recipe original|state_preparation_compiled
--development-root PATH --lazy-root PATH --output PATH` first authenticates
the complete selected development evidence and all four exact lazy-initializer
reproductions. It records all source hashes, benchmark custody, environment,
configuration SHA, algorithm, arms, budgets, seed namespaces, acceptance and
disk forecast in an immutable `DESIGN.json`. This phase never calls a target
loader. The optional state-preparation compiler recipe is eligible only if its
entire separate four-case development comparison passed its fixed promotion
rule; it is never selected from confirmation results.

`--prepare-only --output PATH` authenticates that complete design before loading
any held-out vector. It binds exact q6 vector hashes for all five fixed targets
and both replicas, records the full preparation cost, and publishes the complete
parent `PROTOCOL.json` plus every case manifest before scientific execution.
The parent uses the exact schema enforced by `confirmation_construction`.
Neither that constructor nor the lazy initializer can execute q6 work without
the complete parent hash. The five targets are tfim_ferro, tfim_para,
haar_random_2, haar_random_3 and random_mps_bond3; replicas are11 and29. No CLI
option changes this ten-case product or reduces it to a convenient subset.

`--run --workers 1|2 --output PATH` executes that frozen parent. Recipe, target,
budget or seed changes are forbidden after design freeze. Small synthetic
q1-q3 engineering fixtures can use the Python API with explicitly supplied
vectors and reduced positive budgets; they cannot use the scientific loader
or substitute for any confirmation evidence. There is no engineering CLI.
All four native thread limits (`OPENBLAS_NUM_THREADS`, `OMP_NUM_THREADS`,
`VECLIB_MAXIMUM_THREADS`, `MKL_NUM_THREADS`) must explicitly equal1 at scientific
freeze, preparation and execution. Their values are frozen separately from the
unchanged constructor environment schema.

## Primary comparison and complete-panel rule

For each case, the primary refinement CPU cutoff is the minimum final compiled
endpoint CPU of the four structural roles. Score **all six trained controls and
unchanged** at that same cutoff, selecting their last chronologically available
raw or compiled checkpoint. A shorter completed arm remains deployable at its
final point. No interpolation, best-score selection or comparator filtering is
allowed. Preserve the minimum-six-trained cutoff as a sensitivity panel and
retain all full-cap final endpoints.

For each role and target, average the eleven noisy fidelities across the two
replicas; then average the five target means. Noiseless is retained separately,
not included as a twelfth noisy condition. B* is fixed from development as
structural_mean2_weighted_adam. Also identify the strongest aggregate among
**all** noncandidate roles at the primary cutoff, with deterministic method
order for exact ties. Promotion requires candidate advantage >=0.005 over both
B* and that strongest overall control, and strictly positive target advantage
`>1e-10` on all five targets against each required comparator. Full and sensitivity
panels are supporting evidence; neither can rescue a failed primary gate.

Every one of ten cases, seven roles and twelve profile scores must be complete,
finite and source authenticated. A failed, missing, unknown-cost or malformed
case fails the whole gate; do not calculate a favorable subset mean. No family
is dropped, including difficult Haar states. No further confirmation recipe is
tried after observing these scores.

## Costs, storage and exact resume

Keep full arm and stage optimizer states once in their existing formats.
Outer case records contain compact endpoints, scores, costs, circuit hashes and
arm paths/checksums; do not duplicate raw training histories or curves. Each
new parent phase records running markers, every caught attempt's CPU/wall,
an exact child-file registry and a completion receipt binding every result
field. Completed cache returns verify the complete file set, ledger totals,
source identities and full result checksum. Unknown kills/null durations block
resume; changed fields cannot be authenticated merely by retaining a signature.

Measure target hash binding, per-case input loading, initialization, training,
compilation, evaluation and outer orchestration. Disjoint phase clocks are
nested inside the full physical case clock and are never summed twice. The
shared input/initializer costs and amortized preparation cost enter every arm's
deployable total clock once; optimizer curves retain the developed kernel's
training/ranking/compiler scope. Final and common-cutoff evaluation and outer
bookkeeping remain visible in the complete physical invocation. Exclude only
final publication writes and read-only cached preflight authentication from
that invocation. Full-experiment actual CPU counts common initialization once
per case and all actually executed role/evaluation work, plus batch preparation.
Record worker-lifetime peak RSS at scientific-body completion, with raw units
and normalized bytes (macOS reports bytes; Linux reports KiB). This high-water
mark may include previous worker cases and evidence authentication; it is not
an estimate of incremental algorithm memory.

Before design freeze and launch, require all ten conservative130MiB case bounds
(104MiB maximum observed development child size times1.25) plus512MiB reserve.
Check space at durable case/phase admission boundaries before input loading,
initialization and complete six-arm execution. The unchanged original kernel
has no per-update storage callback; this wrapper does not monkeypatch writers.
Any unexpected storage failure keeps paid checkpoint state and an explicit
failed/incomplete case, and stops promotion. Insufficient storage cannot change
the target or replica panel. Existing scientific artifacts are never deleted or
rewritten to make a selected result fit.
