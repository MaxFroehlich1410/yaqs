# Complete conditional structural composition — development only

This protocol tests a composition of already screened components. It is a new
development method, not confirmation. Only the four original q6 development
targets at replica 11 are used. No confirmation target is constructed or scored.
The coordinator must freeze the complete tested source tree and input hashes
before execution. Earlier numerical source files remain unchanged.

## Hypothesis and shared physical preparation

The target-only rank-two overlap policy has improved fidelity and construction
cost in its complete four-target screen. Exact mean-two deletion and repair has
also improved fidelity. Test whether these gains coexist in a complete recipe,
with all serious optimizers receiving the same opportunities. Known TT-SVD,
quasi-Newton/Adam updates, stratification and the repository's deletion mechanism
are composed; no new optimizer principle or state-of-the-art claim is implied.
Provenance is in INITIALIZER_POLICY_PROTOCOL.md, ENSEMBLE_STRUCTURAL_PROTOCOL.md,
MIXTURE_BASELINE_PROTOCOL.md and LITERATURE.md.

Import the authenticated conditional initializer from the completed
initializer-policy panel: always compute and physically lower rank-two TT-SVD;
use it iff ideal target overlap is at least 0.99, otherwise use the exactly
reproduced legacy construction. Initial compilation is identical for all arms.
Every circuit starts from the physical all-zero state. Full construction,
overlap, discarded probe and initial compiler costs are charged to every arm.
Actual reused execution costs remain separate in the physical development ledger.

The original first-18 protection does not carry a meaningful common identity
across compiled legacy and rank-two circuits. This composition therefore freezes
an **empty protected set for every arm**. Rank every current physical gate for
removal using stable initial physical position ties. Preserve all scalar gate
fields, logical and native identities and surviving optimizer parameter order.
At most fifteen gates can be removed; the input must have more than fifteen
gates so the scalar optimization domain cannot become empty. This changed
protection rule is part of the composition being tested, not an inherited result.

## Arms and bounded work

The primary matched structural panel contains exactly:

- mean-two exact L-BFGS;
- mean-two exact Adam;
- mean-two weighted Adam, 32 paths per channel;
- mean-two adaptive online, 32 paths per channel.

Also run fixed mean-two L-BFGS and fixed noiseless Adam as architecture and
noise-awareness ablations, plus the unchanged compiled initializer. The
noiseless arm is explicitly a fixed-architecture ablation, not a replacement
for the serious structural Adam controls. Every target and condition remains.

Exact mean-two methods use the frozen 3000 constituent-call cap (1500 joint
calls), warmup150, up to15 rounds, shortlist2, equal25-call repairs, history10
for L-BFGS and rate0.02 for Adam. Retained/deleted branches reset moments or
curvature as in their validated exact driver. Weighted/adaptive methods use
1500 charged updates including rejected work, warmup150, up to15 rounds,
shortlist2, repairs25, rate0.02 and preserved surviving memory. Adaptive uses
25 selected-path online updates at0.7 before RMS scaling. Each weighted update
uses 32 paths per channel (64 total) and fresh paired streams from the independent
`composition_training` namespace; sibling repairs share one epoch and future
epochs advance beyond it. Exact finite ranking and branch scoring are charged.
The noiseless Adam ablation receives1500 exact noiseless updates at0.02.
These heterogeneous work caps are not described as equal compute.

Only final accepted L-BFGS iterates and final Adam/online updates are final
endpoints. Structural branches are selected by the frozen exact mean-two
acceptance rule. Rejected branches are never deployable; the incumbent becomes
available only after all round branches and scores finish. Full moments,
secants, stream counters and checkpoint replay costs use the validated drivers.

## Compiler schedule and CPU availability

Compile initially and once after each arm's complete final training endpoint.
This deliberately differs from the fixed-initializer screen's every-ten-update
deployment schedule and is frozen before this composition screen. During
training the actual current physical circuit is deployable without additional
compilation. Its raw accepted checkpoint is available at its recorded cumulative
training CPU. Final compilation is an independent copy, and its compiled
endpoint becomes available only after all compiler and independent ideal-state
audit CPU is charged. Do not retroactively apply final compilation to earlier
checkpoints. Training is not fed a compiled final copy.

Report two predeclared chronological common-CPU panels: the four primary
structural methods, and all six trained methods including the two ablations.
Each cutoff is the minimum final total CPU in that explicit panel. Every arm
uses the same conditional initializer, so its complete initialization cost is
added to every availability time. Select the last available endpoint by CPU
only, without interpolation or score selection. The shorter noiseless ablation
cannot silently redefine the primary structural question; its stricter all-arm
cutoff is reported separately. No unavailable or failed arm is dropped.

The refinement clock includes stage numerical work and intermediate checkpoint
writes, exact structural ranking/selection work and final compiler/audit work.
An inclusive case-attempt timer measures numerical work, evaluation, outer
orchestration, circuit-bank persistence and intermediate arm writes. Its excess
over nested nonoverlapping numerical clocks is separate physical bookkeeping;
never add the inclusive timer and its nested clocks into one CPU total.
Source/custody verification and final case/attempt writes remain outside it.
All final and common endpoints are independently evaluated under all twelve
unchanged conditions, including native Ballarin lowering. Evaluation CPU is
separate. Report full lowered counts, parameters, depth and complete physical
attempt ledgers. Killed operations with unknown CPU block replay until external
accounting; caught failures and replayed work remain charged and visible.

## Decision rule

Promote the complete recipe for confirmation only if its strongest distinct
fair control is beaten at the primary common CPU cutoff by at least0.5 percentage
points mean all-eleven noisy fidelity with four positive target differences,
or if all-target comparable fidelity (no target deficit above0.1 points) is
achieved with at least20% lower two-qubit count or full CPU on every target.
Select one candidate and its strongest distinct primary baseline from this
development panel, then freeze them before confirmation. If no optimizer clears
that rule, retain any supported component/resource result and explicitly decline
an optimizer-superiority claim. Do not change rates, repair budgets, protection,
rank threshold or endpoint policy to rescue individual cases. Any further
composition requires another development protocol, never held-out tuning.
